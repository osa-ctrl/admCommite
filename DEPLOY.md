# Как выложить сайт

Сайт — один Docker-контейнер (Python + FFmpeg + собранная страница).
Подойдёт любой хостинг, который запускает Docker. Главное: задать пароль
и дать серверу немного диска под временные файлы.

## Переменные окружения

| Переменная | Обязательна | Что делает |
|---|---|---|
| `APP_PASSWORD` | да | пароль для входа на сайт |
| `SESSION_SECRET` | нет | ключ подписи cookie; по умолчанию выводится из пароля (смена пароля разлогинит всех) |
| `MAX_ACTIVE_JOBS` | нет | сколько загрузок одновременно, по умолчанию 2 |
| `JOB_TTL_MINUTES` | нет | сколько минут хранить готовый файл, по умолчанию 60 |
| `ALLOW_PRIVATE_URLS` | нет | `1` разрешает ссылки на локальные/внутренние адреса (по умолчанию запрещены) |
| `PORT` | нет | порт внутри контейнера, по умолчанию 8000 |

Список загрузок хранится в памяти: после перезапуска контейнера он пустой,
а временные файлы удаляются.

## Варианты хостинга

**VPS (Hetzner, DigitalOcean, Timeweb и т. п., от ~4–5 $/мес).** Самый
предсказуемый вариант: свой диск и нет ограничений на длительность запроса.

```bash
git clone https://github.com/osa-ctrl/admCommite && cd admCommite
docker build -t ts-web .
docker run -d --restart unless-stopped -p 80:8000 -e APP_PASSWORD='...' ts-web
```

Для HTTPS поставьте перед ним Caddy (`caddy reverse-proxy --from ваш.домен --to :80`)
или Cloudflare Tunnel.

**Fly.io.** `fly launch` подхватит Dockerfile; пароль задаётся
`fly secrets set APP_PASSWORD=...`. Выберите машину минимум с 512 МБ памяти
и одну машину (список загрузок живёт в памяти одного процесса).

**Render / Railway.** Создайте Web Service из этого репозитория, тип Docker,
добавьте `APP_PASSWORD` в переменные окружения. На бесплатных тарифах сервис
засыпает и диск маленький, для длинных видео лучше платный.

## Проверка после запуска

- `https://ваш-адрес/api/health` должен вернуть `{"ok":true,"ffmpeg":true}`
- без пароля `https://ваш-адрес/api/jobs` отвечает 401
